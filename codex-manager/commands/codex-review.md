---
description: 自我流程提问审查：对当前会话或指定项目的流程提出审查问题，生成"可省/可优化/保留"推荐
argument-hint: "[可选：项目名；不填 = 当前会话]"
---

用户要对自己的工作流程做一次提问式审查。核心产出：**按提问逐条给出推荐，明确标注哪些可以省、哪些可以优化、哪些值得保留**，每条都要有事件依据，不许凭空建议。

## 第一步：获取流程

- 参数为空 → 用当前对话梳理本次工作的事件流（用户需求 → 各阶段工具调用 → 产出），规则同 `/codex-flow` 模式 A。
- 参数为项目名 → 读取该项目框架 `%USERPROFILE%\.zcode\codex-manager\projects\<项目名>\flow.json`，把 `versions`（各次搭建的会话事件）与 `stages`（累计阶段）作为审查对象；文件不存在则告知并建议先跑 `/codex-flow-save <项目名>`。

## 第二步：逐条提问并回答（自我审查）

对流程事件流，逐条回答以下审查问题（可按项目情况增删，但不得跳过 1/2/3）：

1. 【可省】哪些步骤的产出没有被后续任何步骤使用？（删掉它省多少时间？）
2. 【可省】哪些步骤重复执行了同一件事？（能否合并为一条命令/一个脚本一次完成？）
3. 【可优化】哪些步骤失败或重试过？根因是什么？下次如何直接绕开？
4. 【可优化】哪些耗时步骤之间没有依赖、本可以并行或提前？
5. 【可优化】哪些环节靠手写重复劳动？（候选：固化为提示词模板或 skill）
6. 【保留】哪些步骤是质量关键点，必须坚持？（防止过度省略）
7. 【习惯】本次流程里有哪些反复出现的个人操作模式？（候选：个人习惯 skill，供 `/codex-habit` 使用）

## 第三步：生成推荐表

以 Markdown 表格输出，列：`类型（可省/可优化/保留/习惯） | 建议 | 事件依据 | 预期收益`。每条建议必须引用具体事件（如"第 3 步连续 2 次 Read 同一文件"），收益尽量量化（次数/分钟）。

## 第四步：落盘

- 参数为项目名时：把本次审查以 inline python 追加进 flow.json 的 `reviews` 数组：
  `{"ts": "<ISO时间>", "questions": [...], "recommendations": [{"type": "可省|可优化|保留|习惯", "text": "...", "evidence": "..."}]}`
  并把第 7 问的答案合并进 `habits` 数组（去重）。
- 无项目名时：把审查结果保存为 `codex-review-<YYYYMMDD-HHMMSS>.md` 到当前工作区。

**诚实原则**：找不到依据的建议不写；事件不足以回答的问题，如实写"证据不足"。
