用户（或流程）宣布一个项目/任务结束，需要做结束总结并产出**优化提示词推荐**。

## 第一步：收集材料

- 参数为项目名 → 读 `%USERPROFILE%\.zcode\codex-manager\projects\<项目名>\flow.json`（versions/stages/reviews/habits 都要用）。
- 参数为空 → 用当前对话 + 已有的审查记录（如有）。
- 如有 usage.jsonl，顺带取该项目会话的调用统计（工具次数、耗时分布）。

## 第二步：写项目总结

结构：`目标与产出 → 实际流程阶段（含每阶段调用次数）→ 遇到的问题与解决 → 遗留事项`。

## 第三步：生成优化提示词推荐（核心）

从流程与审查中找出**反复手写、反复修正、反复解释**的提示场景，每个场景产出一条可直接复制使用的提示词模板，要求：

- 模板含 `$变量` 占位（如 `$文件路径`、`$验收标准`），并在模板下方标注"何时使用、如何填变量"；
- 模板要吸收本项目踩过的坑（把审查发现的教训写进模板的约束条款）；
- 按价值排序，最多 5 条，宁缺毋滥；每条标注来源证据（哪几次重试/纠错催生了它）；
- 对价值最高、且已具备稳定步骤模式的 1-2 条，追加标注 `→ 建议固化为 skill（可运行 /codex-habit 自动编写）`。

## 第四步：落盘

- 项目名模式：总结存入 `projects\<项目名>\summaries\<YYYYMMDD>-<序号>.md`，同时 inline python 把第三步的模板追加进 flow.json 的 `prompt_recommendations` 数组。
- 无项目名：保存 `codex-optimize-<YYYYMMDD-HHMMSS>.md` 到当前工作区。

回复中完整呈现总结与提示词模板（用户要能直接复制），并给出落盘路径。

**诚实原则**：模板必须来自真实发生过的场景；没有足够素材就少写，不硬凑。
