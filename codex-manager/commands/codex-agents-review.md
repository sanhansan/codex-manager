用户要用**多个子智能体**从不同视角并行审查流程，由你（总智能体）汇总。所有子智能体的结论都会沉淀进项目框架，实现**跨智能体总结**（不同会话、不同智能体的发现累积在同一个 flow.json 里）。

## 第一步：准备审查材料

- 项目名模式 → 读 `projects\<项目名>\flow.json`（versions/stages/reviews/agent_summaries）；无框架则先按当前会话梳理事件流。
- 把流程材料（阶段清单 + 各版本摘要 + 已有发现）整理成一段公共背景，供子智能体使用，避免它们重复 your 工作。

## 第二步：并行派出 3 个子智能体（Agent 工具，一次消息同时发出）

| 子智能体 | 审查视角 | 任务要点 |
| --- | --- | --- |
| 效率审查员 | 哪些可省 | 找重复步骤、未使用产出、可合并/并行的环节，给出量化节省估计 |
| 质量审查员 | 哪些有风险 | 找缺少验证、容易出错的环节，建议必须保留的质量关口 |
| 提示词审查员 | 哪些可固化 | 找反复手写的指令与纠错教训，起草可复用的提示词模板 |

每个子智能体的 prompt 必须包含：公共背景 + 它的专属视角 + 输出格式（`发现列表：每条 = 问题 + 证据 + 建议`，不超过 6 条）。使用 general-purpose 子智能体，run_in_background 不需要。

## 第三步：总智能体汇总（不照单全收）

1. **去重与合并**：不同子智能体的同类发现合并为一条；
2. **冲突裁决**：效率审查员想省、质量审查员要保的冲突项，由你给出裁决与理由（默认保守：质量关口优先）；
3. **排序**：按 `收益 × 置信度` 排出 Top 5 行动项；
4. 输出汇总报告：`各智能体发现对照表 → 合并后的 Top 行动项 → 裁决说明`。

## 第四步：跨智能体沉淀（inline python）

把本次汇总追加进 flow.json 的 `agent_summaries`：
`{"ts", "agents": ["效率", "质量", "提示词"], "top_actions": [...], "findings": {...}}`
并在回复中说明：`agent_summaries` 会跨会话累积——**下次任何智能体（包括子智能体）审查该项目时，应先读这部分，避免重复发现同一问题**，从而实现跨智能体总结。

**诚实原则**：子智能体找不到可改进项时，如实写"本轮未发现显著问题"，不硬造建议。
